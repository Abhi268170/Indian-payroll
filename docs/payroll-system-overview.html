SECTION 1 OF 6

Salary Components

A salary component is one line item in an employee's pay — like "Basic Salary" or "House Rent Allowance". Every component belongs to one of five categories.

💰

Earning

Money paid to the employee. Added to gross pay.

  • Basic Salary
  • HRA
  • Special Allowance
  • Statutory Bonus
  • Arrears
✂️

Deduction

Money cut from pay. Monthly or once a year.

  • PF Employee share
  • ESI Employee share
  • Professional Tax
  • LWF Employee
  • Loan recovery
🧾

Reimbursement

Expenses the company pays back. Claim-based, tax-exempt up to limit.

  • Fuel & Maintenance
  • Books & Periodicals
  • Food Coupons
  • LTA
  • Mobile & Internet
🎁

Benefit

Voluntary extra contributions. Not gross, but part of CTC cost.

  • VPF (Voluntary PF)
  • NPS Employee
  • Other Non-Taxable
🔄

Correction

Adjusts a past earning — arrears or reversals. Inherits PF/ESI flags from parent.

  • Links to a parent Earning
  • Can be positive or negative
  • Statutory flags inherited

How an Earning's Amount is Calculated — Formula Types

Every earning component has a formula that tells the system how to compute its monthly amount from the employee's Annual CTC.

Fixed Amount
A flat rupee figure per month. You set it directly.
₹5,000 / month
% of Basic
A percentage of the Basic salary component.
50% × Basic = HRA
% of Gross
A percentage of total monthly gross earnings.
5% × Gross
% of CTC
A percentage of the employee's Annual CTC ÷ 12.
40% × (CTC/12) = Basic
Residual CTC ⭐
Absorbs whatever is left after all other components sum up. Always called "Special Allowance".
CTC/12 − Σ(others)

Why Residual? Every salary structure must have exactly one "Special Allowance" component with formula type Residual CTC. This guarantees that the sum of all components always equals the employee's monthly CTC — no rounding gaps, no leftover amounts.

SECTION 2 OF 6

Salary Structures

A salary structure (called a "template" in code) groups a set of salary components together and defines the formula for each one. You then assign this template to employees.

What is a Salary Structure Template?

Think of it as a pay blueprint. It says: "Employees on this template will have Basic = 40% of CTC, HRA = 20% of CTC, and a Special Allowance that fills the rest."

One organisation can have multiple templates — e.g. one for tech employees, one for sales, one for executives.

Component Slots

Each component in a template gets a "slot" which can override the component's default formula. This means the same component (e.g. HRA) can have different formulas in different templates.

Slots also define the order in which components appear on the payslip.

Three Levels of Formula Override

The system allows overrides at each level. The most specific level wins.

Level 1 — Component Default

Defined on the component itself

When you create the "HRA" component, you set a default formula (e.g. 40% of Basic). This applies everywhere unless overridden.

Lowest priority

Level 2 — Template Slot Override

Defined in the salary structure template

The template can override the formula for this component — e.g. this template uses 50% of Basic for HRA instead of 40%.

Overrides component default

Level 3 — Employee Override

Defined on the employee's assignment

A specific employee can have a personal formula — e.g. their HRA is ₹8,000 flat regardless of CTC. Rare, used for exceptions.

Highest priority

Override-only components: An employee can also have components that don't appear in any template at all — they are added purely via employee-level override. For example, a one-off fixed allowance for a specific employee.

Employee Assignment

Assigning a salary structure to an employee connects a pay blueprint to a specific person, at a specific CTC, from a specific date.

What Gets Assigned?

Salary Structure Template

Which blueprint to use

The template defines which components are in the employee's pay and what formulas to use. Optional — an employee can also have a fully custom structure with just employee-level overrides.

Annual CTC

Total compensation per year

The CTC drives all formula calculations. Monthly CTC = Annual CTC ÷ 12. This becomes the base for "% of CTC" formulas and determines the residual Special Allowance.

Statutory Flags

EPF, ESI, PT, LWF enabled?

Even if the org has PF enabled, individual employees can be exempt (e.g. they are already in a different PF scheme). These flags are set per assignment.

Effective Dates — How Changes Are Handled

One Active Assignment at a Time

An employee can only have one active salary structure. The active one has no end date (EffectiveTo = NULL).

When you assign a new structure, the system automatically closes the previous one by setting its EffectiveTo = today, then creates a new one with EffectiveFrom = today.

History is Preserved

The old assignment record is kept with its end date. This means if you run a payroll for last month, the system can find what the employee's CTC and structure was at that point in time.

Old structure:
CTC ₹5L | EffectiveTo: 2025-03-31
New structure:
CTC ₹6L | EffectiveFrom: 2025-04-01
           | EffectiveTo: NULL (active)
SECTION 5 OF 6

Payroll Run — Step by Step

A payroll run is the process of calculating everyone's pay for one month. It goes through 9 stages, from triggering the run to generating payslips.

1

Trigger & Period Resolution

HR clicks "Initiate Payroll Run". The system figures out which month to process:

  • If a previous run was paid → next calendar month
  • If first ever run → month configured in Pay Schedule
  • Guard: won't create a duplicate run for the same period
2

Snapshot Statutory Config

Fetches all statutory rates from the DB and freezes them into the run record as a JSON snapshot. This ensures the payroll is reproducible — re-running it later gives the same result.

  • PF rates, wage cap, ESI rates, ESI ceiling
  • TDS slabs, standard deduction, rebate limits, cess rate
  • PT slabs for every state where employees work
  • LWF config for those states
3

Determine Salary Divisor & Pay Date

Two modes based on the organisation's Pay Schedule setting:

  • Actual Days → divisor = number of calendar days in the month (28/29/30/31)
  • Fixed Days → divisor = a fixed number set by org (e.g. 26)

Pay date is computed as the last day or a specific day of the month, walked back to avoid weekends/holidays.

4

Build Component Inputs per Employee

For each employee, the system computes the monthly amount for every component in their salary structure:

  • Pass 1 — Template slots in display order. Apply employee-level override if one exists. Resolve formula (Fixed / % CTC / % Basic / % Gross). Track Basic for downstream % calculations.
  • Residual — Special Allowance = Monthly CTC − sum of all other components
  • Pass 2 — Employee-only components not in the template (override-only additions)
  • PF wage resolution — which components count toward PF, based on EPF flags
5

Engine Calculation — In This Order

The payroll engine runs calculators in a fixed sequence. Each step uses the output of the previous:

6

Save Results (Draft State)

Results are saved but the run is in Draft. HR can still make adjustments:

  • Set LOP — enter loss of pay days; engine re-runs automatically with prorated amounts
  • Add one-time earning — bonus, gift, etc. added directly to gross+net
  • Override TDS — manually set TDS for specific employees
  • Skip employee — exclude from this run (can be undone)
7

Approve

HR approves the run. Status changes to Approved. Approval is recorded with timestamp and user. No further changes are allowed after approval.

8

Record Payment

HR records that salaries have been disbursed — payment date, mode (bank transfer, cheque), and reference number. Status changes to Paid. This triggers payslip generation.

9

Generate Payslips

A background job (Hangfire) generates a PDF payslip for each employee, uploads it to MinIO (object storage), and marks the payslip as published. Employees can then download their payslips from the portal.

LOP (Loss of Pay) Proration

How Proration Works

If an employee has LOP days, each component marked CalculateOnProRata = true is scaled down:

Payable Days = Total Days − LOP Days
Prorated Amount = Full Amount × (Payable Days / Divisor)

Example: Basic ₹20,000, 2 LOP days, 26-day divisor
→ ₹20,000 × 24/26 = ₹18,461.54

What Doesn't Get Prorated

Components with CalculateOnProRata = false are paid in full regardless of LOP. These are typically statutory bonuses or fixed allowances that are guaranteed for the month.

PF wage cap proration: when restricted PF is enabled and the employee has LOP, the ₹15,000 cap itself is also prorated proportionally.

Calculation Formulas — Exact Code Logic

Every formula below is extracted directly from the engine source. Calculators run in this order: Gross → PF → ESI → PT → LWF → TDS → Gratuity → Net Pay.

Phase 0 — Build Component Inputs (InitiatePayrollRunHandler · before engine runs)

Resolves each salary component to a monthly rupee amount. Template slots processed in DisplayOrder. Employee-level overrides win over template slots.

━━━ SETUP ━━━
monthlyGross = AnnualCTC / 12
basicMonthly = 0 ← updated when Basic component is encountered
nonResidualSum = 0
━━━ PASS 1 — template components (ordered by DisplayOrder, skip Residual) ━━━
effectiveType = employeeOverride.FormulaType ?? templateSlot.FormulaType
effectivePct = employeeOverride.Percentage ?? templateSlot.Percentage
effectiveFixed = employeeOverride.FixedAmount ?? templateSlot.FixedAmount
monthly amount switch on effectiveType:
PercentOfCTC → round( AnnualCTC × (pct / 100) / 12, 2, AwayFromZero )
PercentOfBasic → round( basicMonthly × (pct / 100), 2, AwayFromZero )
PercentOfGross → round( monthlyGross × (pct / 100), 2, AwayFromZero )
Fixed → effectiveFixed ?? 0
if component.EarningType == Basic → basicMonthly = monthly
nonResidualSum += monthly
━━━ RESIDUAL (Special Allowance) ━━━
residualMonthly = round( monthlyGross − nonResidualSum, 2, AwayFromZero )
← always equals: Monthly CTC − sum of all other earnings
━━━ PASS 2 — employee-only components (overrides with no template slot) ━━━
monthly = ov.FormulaType == Fixed ? ov.FixedAmount ?? 0 : 0
━━━ EPF INCLUSION RESOLUTION ━━━
alwaysPfWage = sum( amount where ConsiderForEpf = true AND EpfRule = Always )
for each component:
if EpfRule == OnlyWhenPfWageBelowLimit:
ConsiderForEpf = ConsiderForEpf AND (alwaysPfWage < pfWageCap)
else:
ConsiderForEpf = ConsiderForEpf (unchanged)

Step 1 — Gross Calculator GrossCalculator.cs

Applies Loss of Pay proration. Computes gross wage, PF wage, and projected annual income passed to TDS.

payableDays = SalaryDivisor − LOPDays
for each salary component:
if LOPDays > 0:
prorated = round( amount × payableDays / SalaryDivisor, 2, AwayFromZero )
else:
prorated = amount (no proration — full month)
GrossWage = Σ prorated ← all components (prorated)
PFWage = Σ prorated where ConsiderForEpf = true ← LOP-reduced PF wage
FullPFWage = Σ amount where ConsiderForEpf = true ← non-prorated PF wage
LOPDeduction = Σ amount − GrossWage
AnnualProjectedGross = GrossWage × MonthsRemainingInFY + PriorEmployerYTDTaxableIncome
← "if this month's gross continues for the rest of FY, what is total annual income?"
SalaryDivisor = calendar days in month (Actual Days mode) OR fixed number set by org (Fixed Days mode, e.g. 26)

Step 2 — PF Calculator PFCalculator.cs

Computes 5 distinct PF sub-components. Returns zero for all if PF is disabled or employee opted out.

━━━ GUARD ━━━
if !PFEnabled OR optOut → all = 0, IsExempt = true, STOP
━━━ RAW PF WAGE (LOP config switch) ━━━
rawPfWage = EpfConsiderSalaryOnLop ? PFWage (prorated) : FullPFWage (non-prorated)
← org config: should LOP reduce the PF wage or always use full month wage?
━━━ EMPLOYEE CONTRIBUTION ━━━
employeePfWage = EpfRestrictEmployerWage ? min(rawPfWage, PFWageCap) : rawPfWage
← PFWageCap = ₹15,000 (restricted mode) or uncapped (actual PF wage mode)
EmployeeContribution = round( employeePfWage × EPFEmployeeRate, 2, AwayFromZero )
← EPFEmployeeRate = 12% = 0.12
VPFContribution = round( employeePfWage × (vpfPct / 100), 2, AwayFromZero )
━━━ EMPLOYER PF WAGE (with optional LOP cap proration) ━━━
employerPfWage = EpfRestrictEmployerWage ? min(rawPfWage, PFWageCap) : rawPfWage
if EpfProRateRestrictedPfWage AND EpfRestrictEmployerWage AND LOPDays > 0:
proratedCap = round( PFWageCap × (SalaryDivisor − LOPDays) / SalaryDivisor, 2 )
employerPfWage = min( employeePfWage, proratedCap )
← prorates the ₹15,000 cap itself when LOP days exist
━━━ EPS (EMPLOYER — PENSION FUND) ━━━
epsWage = min( employerPfWage, PFWageCap ) ← EPS ALWAYS uses statutory cap = ₹15,000
EPSEmployerContribution = min( round(epsWage × EPSEmployerRate, 2), EPSCap )
← EPSEmployerRate = 8.33%, EPSCap = ₹1,250/month
━━━ EPF (EMPLOYER — PROVIDENT FUND) ━━━
EPFEmployerContribution = round(employerPfWage × EPFEmployeeRate, 2) − EPSEmployerContribution
← employer total = 12%; EPF employer = 12% − EPS. Remaining goes to PF account directly.
━━━ EDLI (EMPLOYER — INSURANCE) ━━━
edliWage = min( employerPfWage, PFWageCap )
EDLIEmployerContribution = min( round(edliWage × EDLIEmployerRate, 2), EDLICap )
← EDLIEmployerRate = 0.5%, EDLICap = ₹75/month
━━━ ADMIN CHARGE (EMPLOYER) ━━━
EPFAdminContribution = max( round(employerPfWage × EPFAdminRate, 2), EPFAdminMinimum )
← EPFAdminRate = 0.5%, EPFAdminMinimum = ₹500/month

Step 3 — ESI Calculator ESICalculator.cs

Eligibility is all-or-nothing based on gross wage vs the wage ceiling. No proration.

← ESIWageLimit = ₹21,000/month. ESIPWDWageLimit = ₹25,000/month (Persons with Disability)

← ESIEmployeeRate = 0.75%
EmployerContribution = round( GrossWage × ESIEmployerRate, 2, AwayFromZero )
← ESIEmployerRate = 3.25%

Step 4 — Professional Tax Calculator PTCalculator.cs

Three paths depending on frequency mode. Slab lookup uses gross wage vs state-specific bands.

━━━ GUARD ━━━
if !PTEnabled → 0, IsExempt = true, STOP
━━━ PATH A — HalfYearlySplit (Kerala) ━━━
halfYearGross = GrossWage × HalfYearTotalMonths ← e.g. 6 months in the half-year
slab = lookup( StateCode, frequency="HalfYearlySplit", effectiveDate ≤ today, halfYearGross in [SalaryFrom, SalaryTo] )
if slab found:
totalPt = slab.Amount
floor = Math.Floor( totalPt / HalfYearTotalMonths )
if isLastMonthOfHalfYear:
ptAmount = totalPt − (floor × (HalfYearTotalMonths − 1)) ← remainder goes to last month
else:
ptAmount = floor
━━━ PATH B — Monthly or HalfYearly lump-sum ━━━
slab = lookup( StateCode, frequency ≠ HalfYearlySplit, effectiveDate ≤ today, GrossWage in [SalaryFrom, SalaryTo] )
if slab is null → 0, IsExempt = true, STOP
deductThisMonth = frequency switch:
"Monthly" → true ← always deduct
otherwise → slab.DeductionMonths.Contains(currentMonth) ← e.g. only in Sep(9) and Mar(3)
ptAmount = deductThisMonth ? slab.Amount : 0

Step 5 — LWF Calculator LWFCalculator.cs

Most states have no LWF — those employees are auto-exempt. Haryana uses percentage mode; all others use fixed amounts.

━━━ STATE LOOKUP ━━━
stateConfig = LWFStates.FirstOrDefault( l.StateCode == WorkStateCode )
if stateConfig is null → 0, 0, IsExempt = true, STOP
━━━ WAGE THRESHOLD ━━━
if WageThreshold has value AND GrossWage > WageThreshold → 0, 0, IsExempt = true, STOP
━━━ FREQUENCY CHECK ━━━
deductThisMonth = Frequency switch:
"Monthly" → true
"Annual" → DeductionMonth.HasValue AND currentMonth == DeductionMonth
"HalfYearly" → currentMonth is 6 (June) OR 12 (December)
otherwise → false
if !deductThisMonth → 0, 0, IsExempt = false, STOP ← not exempt, just not this month
━━━ AMOUNT CALCULATION ━━━
if IsPercentageBased: ← Haryana only
EmployeeAmount = min( round(GrossWage × EmployeeRate, 2), RateCapEmployee )
EmployerAmount = min( round(GrossWage × EmployerRate, 2), RateCapEmployer )
else: ← all other states: fixed flat amounts
EmployeeAmount = stateConfig.EmployeeAmount
EmployerAmount = stateConfig.EmployerAmount

Step 6 — TDS Calculator TDSCalculator.cs · New Regime (Section 115BAC) only

Projects annual income, applies slab tax, 87A rebate, surcharge, cess. Spreads remaining annual liability across months left in the financial year.

━━━ TAXABLE INCOME ━━━
taxableIncome = AnnualProjectedGross − StandardDeduction
← StandardDeduction = ₹75,000 (FY26). If taxableIncome ≤ 0 → TDS = 0, STOP
━━━ SLAB TAX (ComputeSlabTax) ━━━
annualTax = 0
for each slab in NewRegimeSlabs (ordered by IncomeFrom):
if taxableIncome ≤ slab.IncomeFrom → break ← income doesn't reach this slab
upper = slab.IncomeTo.HasValue ? min(taxableIncome, slab.IncomeTo) : taxableIncome
slabIncome = upper − slab.IncomeFrom
annualTax += round( slabIncome × slab.Rate, 2, AwayFromZero )
━━━ SECTION 87A REBATE ━━━
if taxableIncome ≤ Rebate87ALimit: ← ₹7,00,000
annualTax -= min( annualTax, Rebate87AAmount ) ← Rebate87AAmount = ₹25,000; wipes out tax completely if ≤ ₹25,000
Rebate87AApplied = true
━━━ SURCHARGE (ComputeSurcharge) ━━━
surchargeSlab = surchargeSlabs.Where( taxableIncome > IncomeFrom AND (IncomeTo is null OR taxableIncome ≤ IncomeTo) )
.OrderByDescending(IncomeFrom).FirstOrDefault()
surcharge = slab is null ? 0 : round( annualTax × slab.Rate, 2, AwayFromZero )
━━━ CESS ━━━
cess = round( (annualTax + surcharge) × CessRate, 2, AwayFromZero )
← CessRate = 4% (Health & Education Cess)
━━━ MONTHLY TDS ━━━
totalAnnualTax = annualTax + surcharge + cess
remainingTax = totalAnnualTax − PriorEmployerYTDTDSDeducted
MonthlyTDS = max( 0, round( remainingTax / MonthsRemainingInFY, 2, AwayFromZero ) )
← spread remaining liability evenly across months left in FY (never negative)

Step 7 — Gratuity Calculator GratuityCalculator.cs

Monthly accrual — an employer cost, never deducted from employee salary.

if !GratuityEnabled OR BasicWage ≤ 0 → accrual = 0, IsExempt = true, STOP
MonthlyAccrual = round( BasicWage × 15 / 26 / 12, 2, AwayFromZero )
← Statutory formula: (Basic × 15 days / 26 working-days-in-month) spread over 12 months
Example: Basic ₹20,000 → ₹20,000 × 15/26/12 = ₹961.54/month

Step 8 — Net Pay PayrollEngine.cs

Simple subtraction. Only employee-side deductions reduce take-home. Employer contributions are cost-centre entries.

NetPay = GrossWage
− TDS.MonthlyTDS
− PF.EmployeeContribution
− PF.VPFContribution
− ESI.EmployeeContribution
− PT.Amount
− LWF.EmployeeAmount
─────────────────────
= NetPay (employee take-home)
PayrollCost (company) = GrossWage + PF.EPFEmployerContribution + PF.EPSEmployerContribution
+ PF.EDLIEmployerContribution + PF.EPFAdminContribution

Rounding Rule

Every intermediate amount is rounded to 2 decimal places using MidpointRounding.AwayFromZero (banker's rounding NOT used — 0.5 always rounds up). This matches statutory expectations.
